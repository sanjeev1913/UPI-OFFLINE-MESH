📡 Architecture: The Three Hard Problems Solved
1. Untrusted Intermediaries & Interception
When sending money in a dead zone, a random stranger's phone carries your packet. What prevents them from reading the amount, recipient, or changing the numbers?
Solution: Hybrid RSA-OAEP + AES-256-GCM. Payload is encrypted using a one-time AES key, and that key is wrapped with the server's RSA public key. Intermediates see only opaque ciphertext. AES-GCM provides authenticated encryption: flipping even 1 bit causes decryption to fail and rejects the transaction.
2. The Duplicate-Storm (Concurrent Deliveries)
Because packets gossip to every device within range, multiple bridge phones may hold the exact same payment. When they all walk outside into 4G coverage at the same moment, the server receives multiple concurrent uploads.
Solution: Atomic PutIfAbsent / Redis SETNX on SHA-256(Ciphertext). Before decrypting, the server hashes the ciphertext and atomically claims it in an idempotency cache. Exactly one thread wins; duplicate deliveries are dropped immediately before ledger execution.
3. Replay Attacks
What stops an eavesdropper from capturing an encrypted payment packet and replaying it weeks later to debit the sender a second time?
Solution: 24-Hour Freshness Window + Cryptographic Nonce. Inside the encrypted payload, the sender includes a unique UUID nonce and signedAt timestamp. The backend strictly rejects any packet older than 24 hours. Because the payload is authenticated by GCM, an attacker cannot forge or alter the timestamp.
